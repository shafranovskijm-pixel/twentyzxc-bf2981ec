# Пакет «Договор + ТЗ + Счёт + Акт» из вкладки «Документы»

## Что не так сейчас
- В ТЗ есть пункт «Соединить с договором», но он работает только если договор уже сохранён в БД (`generated_documents`). При обычном «Скачать» договор сохраняется автоматически — однако в таблице договоров для выбора в диалоге появляются только записи из `contracts`, а не из `generated_documents`. Из-за этого договоры, которые были только сгенерированы (не сохранены отдельной строкой в CRM), не видны в выпадашке.
- Сама связка живёт во вкладке «ТЗ», хотя пользователь работает с пакетом в «Документах».

## Что добавляем
1. **Во вкладке «Документы»**, рядом с кнопкой «Скачать PDF», новая кнопка **«Договор + ТЗ + Счёт + Акт (PDF)»**:
   - Активна, если выбран тип «Договор» и у текущего договора есть привязанное ТЗ (или можно выбрать ТЗ во всплывашке).
   - Сохраняет текущий договор в БД (как обычный «Скачать»), затем собирает единый PDF: Договор → Счёт → Акт → ТЗ. Скачивает файл `Пакет_<номер_договора>.pdf`.
   - Если счёта/акта ещё нет — генерирует их на лету из тех же данных формы (без отдельного клика).

2. **В диалоге «Соединить ТЗ с договором» во вкладке ТЗ** — список договоров теперь объединяется из `contracts` + `generated_documents` (тип = contract), без дублей. Так пользователь сразу видит только что скачанный договор.

3. **Кнопка «Скачать пакет PDF» в меню ТЗ** — оставляем, но подсветим подсказкой почему она серая, если ТЗ ещё не привязано.

## Технические детали
- Новая утилита `buildFullPackagePdf({ contractHtml, invoiceHtml, actHtml, tzPayload })` в `src/lib/tz/bundle.ts` — рендерит каждый HTML в PDF через `html2canvas + jsPDF` и склеивает `pdf-lib`'ом (всё уже есть).
- В `DocumentsTab.tsx`: handler `handleDownloadFullPackage()` — рядом с уже существующим download-flow. Перед сборкой вызывает `saveDocumentToDB`, затем дергает шаблоны `generateInvoiceHtml`/`generateActHtml` (они уже импортированы) и читает ТЗ из `tz_documents` по `contract_id`.
- В `TzTab.tsx`: расширить запрос `contracts` UNION'ом из `generated_documents` (через два запроса и слияние по `contract_number` для уникальности).
