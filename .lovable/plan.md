## Проблемы

1. В карточке клиента → раздел «Договоры» напротив каждого договора нет кнопки скачать PDF. Есть только «глаз», и то показывается лишь если у договора привязан `file_path` в Storage. Скачать сгенерированный договор из этого списка невозможно.
2. При редактировании суммы договора «магически» меняется и счёт. Причина: при пересохранении договора в `DocumentsTab` идёт upsert счёта по `(doc_type='invoice', doc_number=<номер договора>)` — существующий счёт перезаписывается новым `html_content` и `total_amount` (см. `DocumentsTab.tsx:872–902`).
3. Печать/подпись на PDF режется между страницами: `document-pdf.ts` разрезает canvas по фиксированному шагу `pdfHeight - margin*2`, не учитывая блок печати.

## Что сделаю

### 1. Кнопка «Скачать PDF» в списке договоров клиента
Файл: `src/components/admin/ClientsTab.tsx`, `ContractsSection` (≈1399–1447).

Для каждой строки договора:
- Если есть `file_path` → скачивать напрямую из Supabase Storage (bucket `contracts`, `download()`), сохранять как `Договор_<номер>_<дата>.pdf`.
- Иначе ищу связанный `generated_documents` (`doc_type='contract'`, `contract_id = c.id`, самый свежий), рендерю HTML через существующий `generatePdfBlob` и `downloadBlob`.
- Если ни файла, ни сгенерированного HTML нет → toast «Договор ещё не сгенерирован».

Иконка `Download` рядом с текущим `Eye`, спиннер во время загрузки.

### 2. Развязать счёт от последующих правок договора
Файл: `src/components/admin/DocumentsTab.tsx` (≈872–903).

Меняю логику:
- При первом сохранении договора создаётся счёт как сейчас.
- При повторном сохранении договора **счёт больше не перезаписывается автоматически**. Если сумма/услуги в договоре изменились, покажу toast-предупреждение со ссылкой «Обновить счёт» — пользователь явно решает, пересоздавать ли счёт.
- Технически: заменяю безусловный upsert на `insert` только когда `existingInvoice` отсутствует; для существующего — тост «Счёт №… не изменён (сумма договора изменилась). Перегенерируйте вручную при необходимости».

Это гарантирует: правка договора не трогает уже выставленный счёт.

### 3. PDF не режет печать
Файл: `src/lib/document-pdf.ts`.

Подход — «умная разбивка страниц» без изменения шаблонов:
- В HTML-шаблонах (contract/invoice/act и proposal-template — где уместно) оборачиваю блок подписи/печати в `<div data-no-break="true">…</div>`. Уже есть подобные блоки в `document-templates.ts`.
- В `generatePdfBlob` перед `html2canvas` собираю координаты всех `[data-no-break]` внутри iframe (`getBoundingClientRect` относительно body). Считаю их вертикальные диапазоны в px canvas (умножаю на `scale`).
- В цикле пагинации: если очередной разрез страницы попадает внутрь диапазона «не резать» — сдвигаю разрез выше, к началу этого блока (добавляю пустое пространство до конца текущей страницы, следующая страница начинается с целого блока). Если сам блок выше страницы — оставляю как есть (крайний случай).
- Логика реализуется через список «запрещённых» y-диапазонов и корректировку `usable` на конкретной странице.

### Технические детали

- Скачивание из Storage: `supabase.storage.from('contracts').download(path)` → `Blob` → `downloadBlob`.
- Для fallback-рендера использую уже импортированные `generatePdfBlob`, `downloadBlob`, `safePdfFilename`.
- Тип `generated_documents.services` — `Json`, парсинг не нужен для рендера, берём `html_content` как есть.
- Разбивка PDF: сохраняем текущее поведение по умолчанию, если `[data-no-break]` не найдено — работает как раньше.

### Не входит в scope

- Не меняю дизайн PDF-шаблонов, только оборачиваю блок печати атрибутом.
- Не трогаю `ProposalsTab` — там свой шаблон без печати.
- Не меняю схему БД.
