## Проблема

Когда заказчик — ИП (например «ИП Майер Николай Эдуардович»), в шапке договора всё равно подставляется «в лице директора …, действующего на основании Устава». У ИП нет ни директора, ни устава — он действует на основании ОГРНИП.

Сейчас в виде:
> ИП Майер Николай Эдуардович, именуемое в дальнейшем Заказчик, в лице директора , действующего на основании Устава, с другой стороны…

Нужно так:
> ИП Майер Николай Эдуардович, именуемый в дальнейшем Заказчик, действующий на основании ОГРНИП 253615392404, с другой стороны…

## Решение

Добавить общий помощник, который определяет ИП по полю `client.name` (начинается с «ИП ») или `client.ogrn` длиной 15 цифр (ОГРНИП), и возвращает корректную фразу-«вступление».

```ts
// в document-templates.ts
function isIP(cl: ClientRequisites): boolean {
  const n = (cl.name || "").trim().toLowerCase();
  return n.startsWith("ип ") || n.startsWith("индивидуальный предприниматель")
      || (cl.ogrn || "").replace(/\D/g, "").length === 15;
}

function clientIntro(cl: ClientRequisites, role = "Заказчик"): string {
  if (isIP(cl)) {
    const ogrn = cl.ogrn ? `ОГРНИП ${cl.ogrn}` : "ОГРНИП";
    return `<strong>${cl.name}</strong>, именуемый в дальнейшем «${role}», действующий на основании ${ogrn}`;
  }
  const post = declinePost(cl.director_post || "Директор").toLowerCase();
  return `<strong>${cl.name}</strong>, именуемое в дальнейшем «${role}», в лице ${post} ${declineFullName(cl.director_name)}, ${getActingPhrase(cl.director_name)} на основании Устава`;
}
```

Также: для ИП в блоке реквизитов вместо КПП показывать только ОГРНИП (КПП у ИП нет), и в блоке подписей убрать строку «Директор» / должность.

## Где править

1. **`src/lib/document-templates.ts`**
   - Добавить `isIP()` и `clientIntro()`.
   - Применить в шапке договора (строка ~365) и акта/счёта (строка ~223), заменив текущую конструкцию `в лице …, действующего на основании Устава`.
   - В блоке подписей клиента: если ИП — не печатать `cl.director_post`, заменить «М.П.» на «М.П. (при наличии)».

2. **`src/lib/frdo-contract-template.ts`** (строка ~118)
   - Использовать тот же `isIP/clientIntro` (импортировать из `document-templates.ts`) для шапки договора ФРДО.
   - В реквизитах заказчика: для ИП убрать КПП, оставить ИНН и ОГРНИП.

3. **`src/lib/nmo-contract-template.ts`** (строка ~115)
   - То же самое, что и для ФРДО, для договора НМО.

4. **Шаблон акта сверки** (`src/lib/reconciliation-template.ts`)
   - Шапка ссылается на `cl.name` без должности — менять не требуется. Проверить только подписи: для ИП убрать «Директор».

## Технические детали

- Определение ИП основано на префиксе названия и/или длине ОГРН (15 = ИП, 13 = юрлицо). Это устойчиво для DaData-выгрузки, где `name` приходит как «ИП Иванов Иван Иванович».
- Согласование рода: для ИП — «именуемый», «действующий» (м.р.); для юрлица оставляем существующее «именуемое», «действующее».
- Никаких миграций БД не требуется — все нужные поля (`name`, `ogrn`, `inn`) уже есть в `ClientRequisites`.
- PDF-генерация и нумерация документов не затрагиваются.

## Что не меняется

- Реквизиты исполнителя (наша компания).
- Логика номеров документов, рассылки в Telegram, email.
- Шаблоны заявлений/обязательств НМО, где клиент-ИП ранее не вызывал проблем — проверим, но менять только если там тоже есть «Устав».
