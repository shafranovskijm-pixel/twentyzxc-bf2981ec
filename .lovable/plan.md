# Рассылка по расписанию (drip-кампания)

Сделаю систему, где вы один раз выбираете лидов (или просто жмёте «Запустить рассылку на сегодня») — и платформа сама отправляет по 1 письму каждые 10 минут, до 20 писем в день. По каждому письму видно: отправлено / ошибка / ответ. Кнопок в шапке станет меньше.

## Что увидите в интерфейсе

### 1. Упрощённая шапка SalesTab
Сворачиваю кнопки в 2 группы:
- **Главная кнопка «Рассылка»** (оранжевая, заметная) — открывает панель кампании.
- **«…ещё»** (dropdown) — туда уезжают: Импорт XLSX/CSV, Из договоров, Из реестра, Найти лиды (web), Спарсить email, Обогатить ИНН, Шаблон письма, Убрать школы, Экспорт Coldy.

Останутся на виду: поиск, «Только с email», «Есть email», «+ Добавить», «Рассылка».

### 2. Панель «Рассылка» (новый Dialog)
Сверху — статус сегодняшней очереди:
```
Сегодня: отправлено 6 из 20  ·  следующее в 14:20  ·  [Пауза] [Стоп]
```
Под ним — список 20 писем на сегодня с цветными бейджами:
- зелёный «Доставлено», синий «Отправлено», жёлтый «Ждёт», красный «Ошибка: …», серый «Отменено».
Кнопка **«Запустить рассылку на сегодня»** автоматически берёт 20 ближайших лидов со статусом `new` + есть email и ставит их в очередь по 10 минут.
Кнопка **«Добавить выбранных в очередь»** — если отметили чекбоксами конкретных лидов.

### 3. В таблице
Колонка «Лицензия» становится «Рассылка»: показывает «в очереди на 14:20», «отправлено 12.06», «ошибка SMTP».

## Что под капотом

### Таблица `email_campaign_queue`
```
id, lead_id, email, subject, body_html,
scheduled_at timestamptz,         -- когда отправить
status text,                      -- queued|sending|sent|failed|cancelled
attempts int, error text,
sent_at, delivered_at,
created_by uuid, created_at
```
+ RLS: видит только владелец (auth.uid() = created_by) + service_role.
+ Индекс на (status, scheduled_at).

### Edge-функция `process-email-queue` (cron каждую минуту)
- Берёт `status='queued' AND scheduled_at <= now()` LIMIT 1.
- Помечает `sending`, дёргает существующий `send-document-email`.
- На успех → `sent`, на ошибку → `failed` + текст ошибки.
- Дневной лимит 20 проверяется при постановке в очередь.

### Edge-функция `enqueue-campaign`
Вход: массив `lead_ids`, subject, body, `per_day=20`, `interval_min=10`, `start_at`.
- Раскладывает лидов по слотам: первый = `start_at` (по умолчанию now+1мин), далее +10 мин.
- Если на сегодня уже стоит N писем — продолжает с завтра в 10:00.
- Возвращает план: «20 писем, последнее в 17:10».

### Cron
`pg_cron` job раз в минуту вызывает `process-email-queue` (через `net.http_post` с anon-ключом).

### Отчёт
В панели «Рассылка» — вкладка **«История»**: таблица за последние 30 дней с фильтром по дате/статусу + CSV-экспорт.

## Объём работ
1. Миграция: таблица `email_campaign_queue` + GRANT + RLS + индекс.
2. Edge: `enqueue-campaign`, `process-email-queue`.
3. Cron job (через `supabase--insert`, не миграцией — содержит project ref/anon).
4. UI: `SalesTab.tsx` — свернуть шапку в dropdown «Ещё», добавить кнопку «Рассылка».
5. Новый компонент `CampaignDialog.tsx` — очередь сегодня + история + запуск.
6. Колонка «Рассылка» в таблице лидов с подгрузкой ближайшего слота.

## Параметры по умолчанию (можно потом менять)
- 20 писем/день, интервал 10 минут, окно отправки 10:00–18:00 МСК.
- Если запустили в 17:00 — оставшиеся уходят на завтра с 10:00.
- При ошибке — 1 повтор через час, потом `failed`.

Подтвердите — и собираю. Если параметры (20/10мин/окно времени) хотите другие — скажите сразу.
