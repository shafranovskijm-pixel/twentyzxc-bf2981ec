# Карточка клиента: договоры и активность в центре, редактирование — в гармошку

## Цель
Когда открываешь карточку клиента, в первую очередь видеть **движение по клиенту** (договоры, документы, история звонков/писем/заметок), а форму редактирования полей — свернуть в опциональную секцию.

## Новый порядок блоков в карточке

```text
┌─ Шапка ─────────────────────────────────────────────┐
│ Название организации              [Договор][Счёт][Акт][TG][×] │
│ Быстрые факты: тел · email · TG · ИНН · Оплата · Срок услуг   │
└─────────────────────────────────────────────────────┘

▸ Договоры (N)              ← раскрыто по умолчанию
   список с № / датой / суммой / статусом, клик → договор

▸ Активность по клиенту (N) ← раскрыто по умолчанию
   • быстрый ввод: [Тип ▾ Звонок/Письмо/TG/Заметка] [текст…] [+]
   • лента событий с датами, иконкой и удалением

▸ Документы (N)             ← свёрнуто
▸ Задачи (N)                ← свёрнуто

▸ Логины и доступы          ← свёрнуто
   логин ФРДО, пароль ДПО, пароль ПО, дата оплаты, срок услуг

▸ Реквизиты                 ← свёрнуто
   ИНН/КПП/ОГРН/адрес/директор + кнопки «Из договора»/«Синхронизировать»

▸ Контакты и описание       ← свёрнуто
   контактное лицо, телефон, email, telegram, услуга, заметки

[ Сохранить изменения ]     ← закреплено внизу
```

## Что меняем

**Шапка карточки.** Над секциями — строка с фактами клиента (телефон/email/telegram/ИНН/дата оплаты/срок услуг) в режиме «только просмотр» с иконками. Кнопки «Договор/Счёт/Акт/Telegram» остаются на своём месте.

**Активность — новая мини-форма в самой карточке.** Сейчас компонент `ClientHistory` показывает договоры/документы/задачи, но активности (звонки/письма/заметки из `client_interactions`) там нет — она живёт отдельной панелью где-то ниже. Перенесём её внутрь карточки как раскрытую секцию с быстрым вводом: select типа (Звонок / Email / Telegram / Заметка / Встреча), однострочный текст, кнопка «+». Лента — с иконкой по типу, датой и кнопкой удаления. Запросы и мутации к таблице `client_interactions` уже есть — переиспользуем их.

**Гармошка.** Используем `<Accordion type="multiple">` из shadcn. По умолчанию открыты «Договоры» и «Активность». Остальные секции (Документы, Задачи, Логины, Реквизиты, Контакты) — закрыты. Состояние открытых секций запоминаем в `localStorage` по ключу `client-card-sections`, чтобы у каждого пользователя сохранялся свой набор.

**Поля редактирования.** Все инпуты, что сейчас лежат подряд (название, услуга, контактное лицо, телефон, email, telegram, логины/пароли, дата оплаты, срок услуг, реквизиты, заметки) — разносим по трём группам внутри гармошки: «Логины и доступы», «Реквизиты», «Контакты и описание». Поле «Название организации» остаётся в шапке (его всегда видно).

**Кнопка «Сохранить».** Остаётся внизу карточки, сохраняет всю форму как сейчас. Если пользователь не открывал ни одну секцию редактирования — кнопка всё равно работает (значения в state не меняются).

## Технические детали

- Файл: `src/components/admin/ClientsTab.tsx` — правим блок `{showForm && (...)}` (строки ~494–617) и расширяем `ClientHistory` (строки ~755+).
- Используем существующий `Accordion` (`@/components/ui/accordion`) и иконки из `lucide-react` (`Phone`, `Mail`, `MessageSquare`, `StickyNote`, `Send`, `FileText`, `ClipboardList`, `KeyRound`, `Building2`, `User`).
- Активность: переиспользуем существующий `useQuery(["client-interactions", clientId])` и мутации insert/delete (строки ~966–1005). Просто переносим UI выше, внутрь карточки, и компактим под inline-форму.
- В шапке клиента показываем быстрые факты как `flex flex-wrap gap-x-4 gap-y-1 text-xs text-muted-foreground` с иконками; копирование по клику для телефона/email (через `navigator.clipboard.writeText` + toast).
- Состояние раскрытых секций: `useState<string[]>` + `useEffect` sync с `localStorage`.
- Никаких миграций БД — все данные уже есть в таблицах `contracts`, `generated_documents`, `tasks`, `client_interactions`.
- Мобильная вёрстка: шапка фактов переносится по строкам, accordion триггеры — full-width, поля внутри секций — `grid-cols-1 sm:grid-cols-2`.

## Что НЕ меняем
- Таблицу списка клиентов и поиск.
- Импорт из договоров, синхронизацию DaData.
- Логику переходов «Договор/Счёт/Акт» и Telegram.
- Поведение клика по имени организации в табе «Договоры» (по-прежнему открывает эту карточку).
