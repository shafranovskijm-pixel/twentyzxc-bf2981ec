# Карточка клиента: лог звонка по клику и кнопки Скачать/Отправить заново для документов

## Цель
1. Клик по телефону в шапке карточки клиента → не «копировать», а сразу открыть мини-форму «Звонок» с текущей датой/временем и полем для комментария. После сохранения — запись попадает в раздел «Активность по клиенту».
2. В разделе «Документы» рядом с каждым документом — кнопки **Скачать** (PDF на диск) и **Отправить заново** (письмо клиенту с PDF-файлом во вложении, без коротких ссылок на Supabase).

## 1. Клик по телефону = быстрый лог звонка

**Что меняется в шапке (`ClientQuickFacts`).**
Кнопка телефона больше не копирует номер — она открывает компактный диалог «Зафиксировать звонок»:

```text
┌─ Зафиксировать звонок ─────────────┐
│ Клиент: ЧПОУ «УЧЕБНЫЙ ЦЕНТР…»     │
│ Номер:  8 924 375-10-10            │
│ Когда:  [13.05.2026 14:32]  (now)  │
│ О чём договорились:                │
│ [______________________________]   │
│ [______________________________]   │
│                                    │
│ [Отмена]            [Сохранить]    │
└────────────────────────────────────┘
```

- Поле «Когда» — datetime-local input, по умолчанию заполнено `new Date()` в локальной таймзоне.
- Поле «О чём договорились» — textarea, не обязательное (если пусто, сохраняем «Звонок состоялся»).
- На «Сохранить»: insert в `client_interactions` с `interaction_type='call'`, `content` = "📞 {номер}\n{дата/время}\n{комментарий}".  
  Чтобы сохранить выбранное пользователем время (а не only-now), для отображения в ленте префиксуем content явной строкой даты/времени — потому что `created_at` в таблице ставит БД (`now()`), его перетереть нельзя из клиента.
- После insert: invalidate `client-interactions`, toast «Звонок зафиксирован», диалог закрывается. Раздел «Активность по клиенту» автоматически обновляется.

**UX-нюансы.**
- Иконка телефона остаётся, плюс мини-иконка `Phone` остаётся кликабельной. Рядом — маленькая иконка «Копировать» (отдельная кнопка), чтобы старое поведение «скопировать номер» тоже было доступно.
- На длинный клик/правый клик ничего не делаем.
- Если у клиента нет телефона — кнопки нет (как сейчас).

## 2. Документы: Скачать и Отправить заново

**Где меняется.** `DocumentsSection` внутри карточки клиента (раздел «Документы» в гармошке).

Сейчас на каждой строке только иконка глаза (превью). Добавляем справа от глаза две кнопки:

- **Скачать** (иконка `Download`) — генерирует PDF из `html_content` через тот же `html2canvas + jsPDF` пайплайн, что и в `resend-contract.ts`, и сохраняет файл локально через `URL.createObjectURL(blob)` + клик по `<a download>`. Имя файла: `{Тип}_{№}_{дата}.pdf` (например `Договор_253-2026_2026-05-13.pdf`).
- **Отправить заново** (иконка `Send`) — открывает диалог «Отправить документ»:

```text
┌─ Отправить заново ────────────────┐
│ Документ: Счёт №253/2026          │
│ Кому:    [info@company.ru     ]   │
│ Копия:   [                    ]   │
│ Тема:    [Счёт №253/2026 — …  ]   │
│ ☐ Также вложить Договор №253/2026 │  (если у документа есть contract_id и в generated_documents есть договор)
│                                   │
│           [Отмена]  [Отправить]   │
└───────────────────────────────────┘
```

**Логика отправки (важно: файлы как вложения, не ссылки).**
1. Берём `html_content` текущего документа → `generatePdfBlob` → base64.
2. Если отмечен чекбокс «также вложить Договор» — находим связанный документ типа `contract` (через `contract_id` или общий `client_name + doc_number`), регенерируем PDF, тоже base64.
3. Вызываем edge-функцию `send-document-email` с массивом вложений (см. ниже).
4. После успеха пишем в `client_interactions` запись типа `email` с содержанием «✉️ Документ отправлен: {label} → {email}». Раздел «Активность» сразу обновляется.

**Email-шаблон** — без ссылок-кнопок. Только короткий текст:
```
Добрый день!
Высылаем документ(ы) во вложении:
• Счёт №253/2026 от 13.05.2026
• Договор №253/2026 от 13.05.2026
С уважением, Синтагма.
```

## 3. Edge-функция: поддержка массива вложений

В `supabase/functions/send-document-email/index.ts` сейчас принимается одно поле `pdfBase64 + pdfFilename`. Расширяем:

- Добавляем приём опционального массива `attachments: [{ filename: string, base64: string, contentType?: string }, ...]`.
- Если массив пришёл — собираем `multipart/mixed` с HTML-частью и N attachment-частей; иначе — старая логика (одиночное `pdfBase64`) для обратной совместимости с другими местами в проекте (FrdoTab, DocumentsTab уже пользуются единичным attachment).
- contentType по умолчанию `application/pdf`.

## Файлы

- `src/components/admin/ClientsTab.tsx` — `ClientQuickFacts`: новый диалог `LogCallDialog`; `DocumentsSection`: кнопки «Скачать» и «Отправить заново»; новый `ResendDocDialog`.
- `src/lib/document-pdf.ts` (новый) — выносим переиспользуемую функцию `generatePdfBlob(html: string): Promise<Blob>` из `resend-contract.ts`, чтобы не дублировать. `resend-contract.ts` начинает её импортировать оттуда.
- `supabase/functions/send-document-email/index.ts` — поддержка массива `attachments[]` без ломки существующих вызовов.

## Что НЕ меняем
- Существующий `resendContractEmail` и кнопку «Отправить заново» в `ContractsTab` — старый поток с ссылками остаётся для договоров со store-PDF в `contract_files` (там и так берётся файл, не регенерация).
- Таблицу `client_interactions` (никаких миграций).
- Старые письма из `FrdoTab`/`DocumentsTab` с одиночным attachment продолжают работать.
